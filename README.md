## 1. 项目目标

用 Godot 制作一款以侦探调查、剧情反转和逻辑推理为核心的 2D 单人游戏。玩家操控一名侦探重查悬案，通过探索场景、观察细节、询问相关人物、对照证词和组合线索，逐步重构被隐藏的真相。

第一阶段不追求大量内容，而是先完成一个约 20～30 分钟、从开始到结局可以完整游玩的“垂直切片”，验证以下体验是否成立：

- 玩家愿意探索场景并主动发现信息；
- 玩家能从证词和物证之间主动发现矛盾，而不是跟随任务标记自动破案；
- 对话选择既能表达侦探态度，也能用于追问、试探和出示证据；
- 推理结论会改变后续对白、调查权限或结局反馈；
- 操作简单，叙事节奏不被复杂系统打断；
- 美术、声音和文字共同形成统一氛围。

项目文件夹继续使用稳定的英文工作名 `Narrative2D`，第一章与当前游戏标题为《不存在的住客》。

## 2. 推荐的游戏形态

### 推荐方案：横向场景探索 + 询问对证 + 线索推理

玩家控制侦探在若干 2D 场景中移动，调查物品、观察环境、与相关人物交谈；获得线索后，可以用证物追问人物，或在线索板上连接事实并提出假设。游戏不设置战斗，主要张力来自信息差、证词矛盾、人物关系和对真相的逐层重构。

推荐这一形态的原因：

- 比纯视觉小说更有空间感和参与感；
- 比传统点击解谜更容易控制谜题难度和开发规模；
- 能充分利用 Godot 的场景、动画、音频和 2D 光照能力；
- 后续可以自然扩展证词对质、案件重演、人物信任和多结局系统。

### 可选方向

1. **视觉小说型**：立绘、背景和对话为主。制作最稳，文本承载力强，但探索感较弱。
2. **点击调查型**：鼠标操作场景热点，重观察和推理。适合悬疑题材，但谜题设计成本更高。
3. **俯视探索型**：类似小型 RPG 地图，无战斗。空间自由度更高，但地图、美术和寻路工作量也更大。

在用户没有选择其他方向前，后续原型默认按“横向场景探索”推进。

## 3. 核心体验支柱

### 3.1 探索有回报

场景中的可互动物不只是装饰。调查应至少提供一种价值：剧情信息、人物侧写、世界变化、隐藏选择或情绪反馈。

### 3.2 推理由玩家完成

系统负责整理信息和提供反馈，但不直接替玩家说出答案。玩家需要主动找出矛盾、选择要出示的证物，并将两到三条线索组合成可验证的假设。错误推理可以得到人物反应或提示，不轻易造成永久卡关。

### 3.3 后果能够被看见

玩家做出选择后，应通过角色反应、环境变化、后续事件或结局回顾感受到影响，避免只有隐藏数值变化。

### 3.4 节奏克制

第一版避免战斗、复杂合成、大型任务树和大量数值系统。让移动、观察、对话、选择和反馈构成清楚的循环。

## 4. 最小可玩闭环

第一版垂直切片建议只包含：

- 1 桩多年前未解决的核心案件；
- 1 个主要地点，拆分为 3 个小场景；
- 玩家角色和 2～3 个重要角色；
- 8～12 个有效调查点；
- 1 条主线目标；
- 3～5 份证词或证词片段；
- 2 次关键对质；
- 2～3 个需要玩家亲自完成的推理结论；
- 1 次最终指认或真相陈述；
- 2 种结局反馈；
- 基础标题界面、设置、存档/读档和制作人员页。

建议的体验流程：

1. 短开场建立地点、目标和异常；
2. 玩家自由探索，获得物证、环境信息和旧案记录；
3. 询问相关人物，记录证词并观察回避点；
4. 用证物追问，暴露第一层矛盾；
5. 在线索板上组合事实，形成并验证假设；
6. 新结论解锁隐藏地点、补充证词或案件重演；
7. 玩家完成最终指认，并决定如何处理完整真相；
8. 进入结局，展示推理与最终选择的后果。

## 5. 剧情设计框架

正式故事尚待讨论，第一版剧本建议遵循“小地点、旧案件、少数相关人物、强关系”的原则，以有限素材获得较高叙事密度。当前推荐从一桩发生在封闭地点、因证词矛盾而长期悬而未决的失踪案切入。

第一章已确定采用《不存在的住客》。多名证人都记得同一位失踪住客，却对其外貌和习惯给出无法共存的描述；玩家最终发现，著名悬案本身可能只是为了掩盖另一件无人关注的真案。

世界观确定为完全现实。探索过程中通过旧建筑声学、潮湿环境、错位反射、自动落锁、人物暗中行动和认知偏差营造疑似超自然的诡异感，但所有关键异常最终都必须由现实因素解释，并成为有效推理的一部分。第一章发生在架空沿海小城：当代调查为 2008 年，旧案为 1996 年。

- 第一章情节与线索链草案：[`docs/CHAPTER_01.md`](docs/CHAPTER_01.md)；
- 早期候选案件与玩法脑暴：[`docs/CASE_CONCEPTS.md`](docs/CASE_CONCEPTS.md)。

题材可以从以下母题中选择或混合：

- **悬疑**：玩家来到一个看似普通的地点，逐步发现所有人都在回避同一件事。
- **关系**：玩家必须在一次离别、重逢或冲突前，决定是否说出被隐瞒的真相。
- **超现实**：场景会根据记忆或态度发生变化，玩家需要判断哪些内容可信。

剧情文件应使用稳定的事件 ID 和文本键。对白展示文本与逻辑条件分离，以便调整剧情、检查分支和未来本地化。

## 6. 技术方案

### 6.1 引擎与目标平台

- 引擎：本机 Godot `4.6.2.stable.official`；
- 脚本：GDScript；
- 首要平台：Windows 桌面；
- 基准画面：16:9，第一版设计分辨率为 1280×720；
- 输入：鼠标与键盘均可完整操作；架构上保留手柄输入映射；
- 首版语言：简体中文；从数据结构上预留多语言能力。

Godot 官网在本稿撰写时列出的最新稳定版为 4.7.1。当前原型没有必须升级的功能需求，因此先使用已安装的 4.6.2；正式制作前再单独评估升级。

### 6.2 计划中的核心模块

- `GameState`：保存剧情标记、已调查内容、角色态度和当前章节；
- `DialogueManager`：读取对话数据，处理条件、选择和效果；
- `InteractionSystem`：检测可互动物、显示提示并触发事件；
- `EvidenceDatabase`：管理物证、证词、人物资料、来源与可信度；
- `DeductionBoard`：让玩家连接线索、提交假设并接收验证反馈；
- `SceneRouter`：切换场景、入口位置与过场；
- `SaveSystem`：保存剧情进度和设置；
- `AudioManager`：管理背景音乐、环境音和界面音效；
- `UI`：对话框、选择项、暂停菜单、设置与存读档界面。

建议对白结构采用数据驱动方式：剧情结构与事件效果使用 JSON 或 Godot Resource，实际文本使用稳定文本键；待原型验证编辑体验后再确定最终格式。简单存档可以使用 JSON，写入 `user://`。Godot 官方文档指出 JSON 易读、易调试，但不适合直接表示 `Vector2` 等复杂类型，因此存档只保存必要的标量、ID 和字典数据。

## 7. 美术与声音策略

目前推荐先使用许可清楚的占位素材验证玩法，视觉方向确定后再决定保留、统一重绘或生成原创素材。

### 推荐的视觉方向

- **低分辨率手绘/像素混合风格（推荐）**：制作量可控，环境氛围突出，适合小团队迭代；
- **平涂插画风**：角色表现力强，但立绘、表情和背景的一致性要求较高；
- **拼贴与剪影风**：容易建立独特气质，适合悬疑或超现实主题。

### 素材来源原则

- [Kenney](https://kenney.nl/assets)：官方说明其资源页面中的游戏素材采用 CC0，可优先用于 UI、图标和原型占位；
- [OpenGameArt](https://opengameart.org/)：只使用已逐项核对许可证的素材；CC0 优先，CC BY 素材必须按要求署名；
- [Freesound](https://freesound.org/)：音效逐项检查许可证，原型优先选择 CC0，暂不采用带 NC 限制的素材；
- [Google Fonts](https://fonts.google.com/)：字体逐项保存许可证文件，并确认包含所需中文字符；
- itch.io 等平台上的素材不能按“网站整体免费”处理，必须以具体素材页面的许可证为准。

任何下载并纳入项目的第三方素材，都要在 `docs/THIRD_PARTY_ASSETS.md` 登记名称、作者、原始链接、许可证、下载日期和修改情况。当前五项 CC0 声音已按此规则登记；其余候选在采用前仍需逐项复核。

AI 合成配音不混入第三方下载素材表；其模型、系统音色、台词来源、生成清单和人工确认状态单独记录在 `docs/VOICE_PRODUCTION.md`。试听确认前不将候选音色接入正式对白。

## 8. 开发阶段

### 阶段 A：概念定型

- 确定案件概念、侦探身份、核心冲突和叙事视角；
- 选择游戏形态与美术方向；
- 写出案件真相、表层谜面、关键误导和主要结局；
- 从真相反推完整线索链，检查玩家能否独立得出结论；
- 明确垂直切片的内容边界。

### 阶段 B：灰盒原型

- 创建 Godot 项目和输入映射；
- 完成角色移动、碰撞、互动提示和场景切换；
- 完成可运行的对话、证物出示和线索组合系统；
- 用纯色占位图跑通一个完整事件。

### 阶段 C：垂直切片

- 加入完整短篇剧本、调查点和两个结局；
- 加入存档、设置和基础声音；
- 统一占位美术或制作首轮正式素材；
- 完成从标题画面到结局的全流程测试。

### 阶段 D：评估扩展

- 根据试玩反馈调整叙事节奏和操作；
- 决定扩展为完整游戏、增加章节，或将垂直切片作为独立短篇完成；
- 再评估多语言、手柄、Web 构建及其他平台。

## 9. 首版暂不包含

除非题材明确需要，第一版暂不做：

- 战斗和角色成长；
- 复杂背包、合成与传统解谜链；
- 未经试听确认就直接制作或接入全程配音；
- 大地图和大量 NPC 日程；
- 在线功能、账号或云存档；
- 自制可视化剧情编辑器；
- 超过两个主结局的大型分支树。

这些限制是为了尽快得到一个完整可玩的作品，而不是永久排除相关功能。

## 10. 主要风险与控制方式

- **分支膨胀**：采用“局部差异、关键汇合、结局反馈”的结构，先限制为一个关键分叉；
- **反转依赖突发信息**：所有关键事实必须在结局前以可观察形式出现，反转只改变玩家对事实的解释；
- **线索组合穷举**：只允许少量有语义的线索连接，给出分类和上下文反馈，避免玩家逐项试配；
- **素材风格不一致**：占位素材与正式素材分开，确定艺术规范后再批量替换；
- **文本修改牵动代码**：用事件 ID、文本键和数据文件分离剧情内容与执行逻辑；
- **玩家不知道能调查什么**：统一互动轮廓、提示图标和距离反馈；
- **存档因剧情修改失效**：为存档增加版本号，只保存必要状态；
- **做了很多系统却没有完整故事**：每个阶段都以“能从开头走到一个结局”为验收目标。

## 11. 下一轮需要共同决定的事项

按优先级讨论以下问题：

1. **配音定稿**：确认六名发声角色的音色、旁白是否全程配音，以及重复调查提示是否配音；
2. **美术深化程度**：保留当前克制手绘方向时，优先补人物动画、调查物特写还是更多场景层次？
3. **后续尺度**：在第一章试玩反馈之后，决定制作后续独立案件，还是扩展侦探自身的长期故事线。

第一章的现实规则、案件舞台、侦探身份、真相和结局结构已经确认；灰盒阶段与首轮美术、基础声音接入已经完成，六名角色试听包等待确认。下一步先锁定声音，再制作并接入正式台词，不预先扩大内容范围。
