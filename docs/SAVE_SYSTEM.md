# 三槽存档（2026-09-05）

## 玩家操作

- 标题的“读取存档”打开固定三个档位，显示编号、是否当前档、章节、地点、保存时间和线索数。空档与损坏档不可读取。
- “新调查 · 第一章”打开档位选择；空档直接开始，已有档位需要确认覆盖。新调查的章节解锁和结局从零开始。
- 游戏中结束对白或退出调查界面后按 Esc，在暂停菜单保存/读取。存入其他档位可分出一条路线；存入已有档位先确认覆盖。
- 每个档位提供“删除”按钮，空档禁用，损坏档也可删除。确认框默认聚焦取消；确认删除后立即刷新为空档。标题和游戏内存读档菜单均可操作。
- 删除当前档位只删除磁盘存档，不中断正在进行的游戏；解除当前档位绑定，暂停自动保存，直到玩家再次手动存入某个档位。点击“保存并返回标题”时会先要求选择保存档位。
- 剧情自动保存只更新当前档位，手动保存到其他档位后，当前档位随之切换。要保留一个分支点，应另存到另一个档位后继续。
- 后续章节使用当前档位的结果，开始章节会提示它会替换当前调查并保留已完成章节结果。
- 通关存档仍占一个档位，读取后展示该章结局，可返回标题进入已解锁章节。
- 保存失败时显示错误并保留当前游戏；“保存并返回标题”写入失败时不会离开场景。

## 数据范围与兼容

`slot_1.json`、`slot_2.json`、`slot_3.json` 位于 Godot 的 `user://` 用户数据目录中。每份包含版本、线索、剧情 flags、章节结果/解锁所依赖的 profile 和时间戳；手动保存额外记录主角水平位置。设置仍使用统一设置文件。

不另设第四个自动存档。文件先写到同路径临时文件，flush 并关闭成功后再重命名替换目标，避免直接截断原档。它不是额外的历史备份或云存档。

首次发现三个档位都不存在时，将旧版 `chapter_01_save.json` 与 `progression.json` 合并迁入存档 1，旧文件不删除、不再作为可选档位。仅有旧通关档案时导入为“旧版通关档案”，读取后回到章节选择。任何档位已存在时均不再次迁入，避免覆盖新进度。

删除前写入 `slots_initialized.json` 标记，防止玩家把所有档位删完后，重启又从旧版备份中恢复一个档。该文件只有初始化标记，不保存游戏进度，不占第四个档位。无法写入标记或无法删除目标时报告失败。

启动时标题显示最近保存的有效档位的章节历史；读取其他档位后使用其历史。旧版跳章档仍可读，缺失的前章记录不会自动补齐。

保存恢复地点、线索、剧情状态和手动存档时的水平位置；不序列化播放到一半的语音、未提交的谜题草稿、逐句对话光标或人物动画相位。自动保存继续沿用剧情节点检查点。

## 验证

- `tests/save_slots_test.tscn` 在 `.godot/slot_tests/` 的独立目录验证三个档位、非法编号、独立新游戏、结局与解锁回滚、自动保存不改动其他档、覆盖确认、损坏档拒绝、写入失败保持原状态、实际标题读档跳转、通关档保留、位置恢复和旧版迁移。
- 五章自动通关和章节顺序/人物表现回归全部通过。
- 删除增量回归覆盖：确认前不删除、取消保留文件、损坏档删除、非法编号、删除其他档不影响当前档、删除当前档不重建、全部删除后不再迁移旧备份、手动保存后恢复自动保存。
- `tests/save_slots_visual_capture.tscn` 在独立目录创建展示数据，检查读取菜单、暂停菜单、保存菜单及覆盖确认，截图输出 `.godot/qa/save_slots/`。
- Godot 4.6.2 导入检查、Windows 导出及导出程序启动检查。快速退出时原有音频播放资源清理警告仍可能出现，存档断言不受影响。
